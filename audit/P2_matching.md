# P2 稽核：配對層

重跑：

```bash
python3 -m src.ptt.transform --source pttcc
python3 -m src.audit_matching --sources pttcc
```

主樣本 = 2020-01-01 ~ 2024-12-31。2019 為暖機期，只進回顧窗，不計入本表。

## 1. 配對結構（`audit/ptt_match_structure.csv`）

| | v2（pttcc, 2020–2024） | v1（pttweb, 2015–2024） |
|---|---:|---:|
| 語料文章 | 143,637 | 251,858 |
| 有配對文章 | 47,583 → **30.0%**（含 2019） | 62,888 → 25.0% |
| ticker-article 列 | **122,562**（主樣本） | 171,073 |
| 命中 ticker 數 | 266 / 267 | — |
| 獨立發文帳號 | **6,101** | 不可得 |

比對模式的分布與 v1 幾乎重合，說明七道規則移轉到新語料後行為一致：

| `match_mode` | v2 | v1 |
|---|---:|---:|
| `code`（代號） | 68.6% | 70.6% |
| `name`（一般簡稱） | 17.0% | 15.1% |
| `name_with_context`（需上下文） | 14.4% | 14.2% |

**配對率上升（25.0% → 30.0%）與刪文選樣一致**：被刪的多為短篇 `請益`／`心得`
（中位 303 字 vs 對照 636 字），這類文章本來就較少提到具體代號。存活下來的文章
配對率較高，不是比對規則變好了。

## 2. 大量清單型貼文：修正了 v1 的定義缺陷

v1 的 `is_bulk_listing` **只數宇宙內命中的 ticker**，因此一篇「跌入處置股風險統計
排行」列了 151 個代號、宇宙內只命中 13 檔時完全逃過旗標。v2 改為兩個判準的聯集
（`PROJECT.md` §4）。主樣本 122,562 列的實測：

| 判準 | 標記列數 | 佔比 |
|---|---:|---:|
| v1（宇宙內 ticker > 15） | 47,944 | 39.1% |
| 全文代號 > 15 | 66,632 | 54.4% |
| **聯集（v2 採用）** | **66,719** | **54.4%** |
| 只有 v1 判準抓到（聯集保住，不損失） | 87 | 0.07% |
| **只有代號判準抓到（v1 漏掉）** | **18,775** | **15.3%** |

進入主規格的列數因此由 74,618 降為 **55,843**（−25%）。這是測度正確性的修正，
不是事後調門檻。修正在跑出任何係數之前定案，且被排除的是資料傾印，與關注度高低
無關。

**bulk 旗標向下傳遞到留言是必要的，不是保險**：留言層有 4,325,229 列（30.9%）
繼承 bulk 旗標。沒有向下傳遞的話這 430 萬列會全數進入 `att_comment_*` 與
`att_users_*`，汙染量是 v1 文章層的數十倍。

## 3. 【核心結果】v1 的窗口指派低估週末關注度 **22.4%**

`docs/PLAN_V2.md` §2-1 的問題可以**直接量**，不需要任何回歸：同一批留言，一次用
母文章時戳指派窗口（v1 只能這樣做），一次用留言自己的時戳指派（v2 的作法）。

主樣本、排除 bulk 後的留言中（`audit/ptt_window_displacement.csv`）：

| | 則數 |
|---|---:|
| 用**文章**時戳算的週末留言（v1 的作法） | 791,134 |
| 用**留言**時戳算的週末留言（v2 的作法） | **967,655** |
| 差額 | **+176,521（+22.3%）** |

位移是**單向的**：

| 位移方向 | 則數 |
|---|---:|
| 平日發文 → 週末留言 | **237,802** |
| 週末發文 → 平日留言 | 61,281 |

平日→週末的位移是反向的 **3.9 倍**。關注度在時間上往週末流，而把它壓在發文那
一刻會系統性地把它留在平日。

**必須精確陳述的界線**：

- 這是**兩個測度之間的差**，不是「v1 算錯了」。主規格量的是**文章數**，而一篇
  文章的發文時刻本來就是它自己的事件時刻，因此就文章而言 v1 的指派是對的。
- 這一項成立的前提是「留言也算關注度」。若採此定義，則 v1 的文章層測度
  **在建構上無法**捕捉 22.4% 的週末關注度，因為舊語料的推文沒有時戳。
- 因此 `att_comment_*` 與 `att_users_*` 是 H1 的**第二條證據線**，不是主規格的
  替代品（`PROJECT.md` §2.4）。

## 4. 獨立帳號數：比發文數更接近原論文的 SVI

| | 數量 |
|---|---:|
| 獨立**發文**帳號（主樣本） | 6,101 |
| 獨立**留言**帳號（全期） | **85,817** |

差距 14 倍。原論文的 SVI 量的是「有多少人在搜」，而 v1 只能數「有多少篇文」，
這些文只代表 6,101 個發文者。`att_users_*` 把母體擴大到 85,817 個帳號，在建構上遠比
發文數接近 SVI。這一項是否讓 `PROJECT.md` §4.1 的測度效度（v1 的 corr 0.939 /
0.403）改變，是 T13 必須重算的。

這對 T14 是好消息：B→C 的差異**不會被樣本大小驅動**，兩者的分析列數實質相等。

### 重建正確性驗證

以 `ptt.source=pttweb` 跑全期（2015-04 ~ 2025-01）：**251,858 篇 → 62,888 有配對
（25.0%）→ 171,073 列**，與 v1 發表的數字逐項相同。v2 的程式重現得了 v1。

### 兩個語料的文字差異（已量化，不影響結論）

同一篇文章在兩個語料中：代號數相同 88.7%、ticker 數相同 98.4%、**bulk 旗標相同
100%**。

`pttweb` 的內文系統性較長（87.8% 的同文如此，中位 737 vs 660 字），多出來的是
**PTT 頁尾（※ 發信站、文章網址）與簽名檔**，v2 的爬蟲把它們剝掉了。

簽名檔是使用者的固定樣板：若某人的簽名檔提到個股，v1 會在他**每一篇**文章都算一
次。實測 4,663 篇有額外文字的文章中，額外文字本身能配到個股的只有 26 篇
（**0.56%**），貢獻 30 個 ticker 配對。**量級可忽略**，但 v2 的文字確實較乾淨。
