## 2. 這次重做要回答的問題

v1 的結論是「證據不足以區分資訊處理與價格壓力兩條管道」，且 H1 週末係數
t = 1.80（p = 0.073）擦邊未達 5%。v2 不是重跑一次求顯著，而是回答：

1. **測度粒度**：v1 把一篇文章的全部關注度壓在「發文那一刻」的窗口。
   實際上一篇週五 22:00 的文章，其留言大量落在週六日。
   用有時戳的 1,439 萬則留言重切窗口後，週末／非交易時段的關注度是否被 v1 系統性低估？
2. **測度建構**：v1 的關注度是「文章數」，原論文的 SVI 是「有多少人在搜」。
   有帳號後可算**獨立帳號數**，這是比發文數更接近 SVI 的建構。
   v1 的測度效度（corr 0.939 / 0.403 vs 論文 Table 2 的 0.90 / 0.40）
   在獨立帳號數下是否仍成立？
3. **語料完整性**：鏡像站封存與官方站直爬在 2020–2024 重疊區的差集有多大？
   v1 的結果有沒有一部分是鏡像缺漏造成的？

## 3. 期間改為 2020–2024 的後果（必須先認列）

### 3.1 H4 補班日自然實驗：**完全消失，不是檢定力不足**

實際交易日曆中補班星期六共 9 天，**2020–2024 為 0 天**
（TWSE 自 2019 年起不再補行交易）。v1 還有 8 個事件週可做探索性訊號，
v2 **一個都沒有**。

→ H4 自 v2 的假說清單移除，`src/analysis/makeup_days.py` 在 v2 設定下應
**明確 SKIP 並寫入 `audit/model_status.csv`**，不得靜默略過。

### 3.2 暖機期：52 週稀疏度回顧窗會吃掉 2020 一整年

- `abn_attention` 需 8 週回顧（`min_periods: 8`）→ 2020 前 8 週為缺值。
- `sparsity_tier` 需 **52 週**滾動回顧 → **2020 全年 tier 為缺值**，
  H6 異質性與 dense/sparse 子樣本在 2020 完全沒有觀測。

兩個處理選項，**建議 (a)**：

| | 做法 | 代價 |
|---|---|---|
| **(a) 補爬 2019 全年當暖機期** | 只進入回顧窗，不進入主樣本 | 約 30–60 分鐘爬取、~600 MB；主樣本仍為 2020–2024，不違反 §0 的決策 |
| (b) 不補爬 | 主樣本起點改為 **2021-01-01**，或接受 2020 全年無 tier | 260 週 → 208 週，或 H6 少掉五分之一觀測 |

決定後寫入 `config/settings.yaml` 的 `sample.ptt_warmup_start`，**在看到任何結果之前定案**。

> **已選 (a)**，且另加一項前提：52 週窗必須**滿窗**（`sparsity_min_periods: 52`）。
> 舊版的 `min_periods` 是 1，那樣沒有暖機期也不會報錯，只會用殘缺窗算出偏向
> `silent` 的錯值，補爬 2019 的理由也會因此無法驗證。

## 4. 新資料開啟的測度（§0 決策：主規格不變，這些是平行測度）

| 測度 | 定義 | 為什麼值得做 |
|---|---|---|
| `att_comment_*` | ticker×週×窗口的**留言則數**，用留言自己的時戳切窗口 | 直接檢驗 §2-1：週末關注度是否被 v1 低估 |
| `att_users_*` | ticker×週×窗口的**獨立留言帳號數** | 最接近原論文 SVI 的建構（有多少人，不是有多少則） |
| `att_authors_*` | 獨立發文帳號數 | 同上，文章側 |
| `author_hhi` | 該 ticker×週關注度的發文者集中度 | 長尾個股的「關注度」可能只是同一人反覆發文；這是 v1 無法排除的替代解釋 |
| `push_boo_ratio` | 推／噓比 | 選配。**不列入主假說**，僅記錄於稽核表 |

### 4.1 留言的 ticker 歸屬（必須寫死的假設）

留言**繼承母文章配對到的 ticker**，不對留言文字另行比對代號。理由：留言短、
常見「2330」等數字在留言中同樣有量詞誤配風險，而 v1 已證實排行表數字欄是六類
誤配之一。此假設寫入 `PROJECT.md` 並做一項穩健性：另外比對留言文字中的代號，
比較兩者的 H1 係數。

**`is_bulk_listing` 必須向下傳遞到留言**：一篇列 242 檔的程式選股文，其留言
會一次繼承 242 個 ticker，不排除的話會比 v1 的汙染更嚴重。

### 4.2 留言時戳的缺值

留言 `time` 約 0.01%（全期約 1,500 則）為空。依專案規則**缺值維持缺值**：
這些留言不進入任何窗口測度，但計入「留言總數」的稽核數字，差額寫入
`audit/ptt_comment_coverage.csv`。跨年推文的年份回推需另做一項驗證
（12 月文章的 1 月留言）。
