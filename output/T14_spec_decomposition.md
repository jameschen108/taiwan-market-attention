重跑：

```bash
for s in C B A_prime; do python3 -m src.features.build --spec $s; done

```

**本表比較的是面板層的測度統計，不是係數**——P4 尚未開跑。係數層的分解要等 H1
跑過三個規格之後，屆時本表會是它的上半部。

規格 A 不重跑：它是 v1 既有的發表結果，用 v1 的程式與定義產出，數字引自 v1 的
`output/`。因此 **A→A′ 只有少數幾欄可比**，不是逐欄對照。

## 1. A → A′：測度定義效果**最大**，而且方向是往壞的

同一份語料、同一個期間，只換成 v2 的定義：

| | A（v1） | A′（v2 定義） | 差 |
|---|---:|---:|---|
| 零關注度率 | 0.797 | **0.848** | **+5.1pp** |
| dense 檔數 | 36 | **22** | **−39%** |
| bulk 排除（列） | 42.7% | **56.6%** | +13.9pp |
| 列數 | 123,828 | 123,333 | −495（週涵蓋規則） |

**這一欄是四方對照裡最大的一項。** 它不是換資料造成的，是**我們自己做的四項測度
修正加上 bulk 三判準**造成的：bulk 排除率由 42.7% 升到 56.6%，被排除的那些列
原本會讓許多 ticker-week 由零變非零，dense 檔數因此從 36 掉到 22。

**這反轉了 `docs/PLAN_V2.md` 的預期。** 計劃假設 v2 與 v1 的差異主要來自語料
（B→C），實測是**測度定義（A→A′）遠大於語料（B→C）與期間（A′→B）**。
`LIMITATIONS.md` §14 要求補 A′ 是對的——沒有它，這一整段會被錯誤歸因到換資料。

**可比性的界線**：v1 的 36 檔 dense 是在 506 週、`sparsity_min_periods=1` 下算的；
A′ 是 504 週、`min_periods=52`。兩者不是同一個估計量，`−39%` 是兩個定義下的差，
不是同一定義下的變化。這一段只能做**方向與量級**的判讀。

## 2. A′ → B：期間效果

| | A′（全期） | B（2020–24） |
|---|---:|---:|
| `att_all` 均值 | 0.591 | **0.815**（+38%） |
| 零關注度率 | 0.848 | 0.824 |
| dense 檔數 | 22 | 21 |
| tier 缺值率 | **0.097** | 0.000 |
| `dt_ratio` 均值 | 0.126 | **0.177** |

2020–2024 的發文密度比全期高 38%，當沖率高 40%——與「COVID 股災 ＋ 當沖狂熱」的
期間特徵一致（`LIMITATIONS.md` §4）。

A′ 的 tier 缺值率 9.7% 全部落在前 52 週：封存起點 2015-04-27 之前沒有資料可回顧，
`sparsity_min_periods=52` 因此維持缺值。**這正是 v2 修正的那一項**——v1 用
`min_periods=1` 會在那段期間用殘缺窗算出偏向 `silent` 的錯值。

## 3. B → C：已刪文流失的影響**遠小於文章層的 14%**

這是本表最反直覺的一格。`audit/P0_corpus_integrity.md` 量到新語料在文章層是舊封存
的真子集，**少 14.06%（23,505 篇）且刪文非隨機**。但到了關注度面板：

| | B | C | 差 |
|---|---:|---:|---|
| `att_all` 均值 | 0.8148 | 0.7800 | **−4.3%** |
| `att_weekend` 均值 | 0.1304 | 0.1265 | **−3.0%** |
| 零關注度率 | 0.8238 | 0.8240 | +0.02pp |
| dense 檔數 | 21 | 21 | 0 |

**總量相近可能只是巧合，所以必須做格子層對照**（`T14_cell_level_B_vs_C.csv`）：

| | 值 |
|---|---:|
| corr(`att_all`) | **0.9951** |
| `att_all` 完全相同的格子 | **94.8%** |
| corr(`att_weekend`) | 0.9866 |
| `att_weekend` 完全相同 | 98.4% |
| corr(`abn_attention_weekend`) | **0.9160** |
| `sparsity_tier` 相同 | **96.0%** |

而且差異**大致對稱**，不是單向流失：`att_all` 上 C < B 佔 2.8%、C > B 佔 2.4%。
在任一邊非零的 11,988 個格子中，相同 71.7%、C 較低 15.2%、C 較高約 13%。

**為什麼 14% 的文章流失只換來 3–4% 的關注度流失**：被刪的多為短篇 `請益`／`心得`
（中位 303 字 vs 對照 636 字），這類文章 (a) 本來就較少提到具體代號、(b) 即使提到，
那個 ticker-week 通常還有其他文章撐著，計數少一篇不會由非零變零。

**C > B 的那 2.4% 從哪來**：兩個語料對同一篇文章的**文字不同**——pttweb 保留 PTT
頁尾與簽名檔，pttcc 剝掉了（`audit/P2_matching.md` §6）。同文的 ticker 數一致率
98.4%，不一致的部分兩個方向都有。

### 判讀

`LIMITATIONS.md` §2 把已刪文列為「v2 最重要的一條限制」。**就關注度面板而言，這
一條的實測影響小於預期**：格子層相關 0.995、tier 一致 96%。

但**不得據此撤銷該條限制**，三個理由：

1. 本表比的是**文章計數測度**。留言與獨立帳號測度只存在於 C，沒有 B 可對照，
   刪文對它們的影響**無法以同樣方式檢驗**。
2. 刪文的**分層偏斜**仍然成立（`mid_effort` 保留 75.1%、`low_effort` 92.7%）。
   H2 用的是分層之間的對比，那個對比仍被改動過。
3. 相關 0.995 是**橫斷面**的一致性。若殘留的 5% 差異系統性地落在高關注度的格子上，
   對尾部的影響會大於平均數所顯示的。這一項尚未檢驗。
